# 룬PT 기존 앱에 화면만 병합하는 프롬프트

운영 중인 `upvible/Rune-PT` (`index.html`, `avatar/`, `sw.js`, GitHub Pages `https://upvible.github.io/Rune-PT/`)에 이 저장소의 화면을 올린다. 티어 계산, 세트 기록, 동기화, 로그인, 선물함, 트레이너 화면은 그대로 두고, 회원 화면의 배치와 말만 바꾼다.

시각 기준은 `design-review/proposed/` 여섯 장과 `design-review/개선-프롬프트.md`다. 숫자와 종목 이름은 예시가 아니다. 실행 중인 `S`, `EXERCISES`, `draft()`, `GIFTS`를 그린다.

Path A(`apps/web`, `packages/core`)는 생김과 카피의 참고다. 그 코드를 운영 앱 자리에 덮어쓰지 않는다.

## 합치는 방법

`chjisceo/rune-pt`와 `upvible/Rune-PT`는 커밋 조상이 다르다. `git merge`, `git pull`로 한 브랜치에 넣지 않는다. 운영 저장소 `main`에서 브랜치를 따고, 아래 허용된 차이만 커밋한다.

`index.html`은 약 545KB 한 파일이다. 줄을 재정렬하거나 포매터를 돌리면 다른 수정과 전부 충돌한다. 손대는 곳은 아래 다섯 군데뿐이다.

1. `<head>`에 스타일시트 한 줄. 새 파일 `ui/path-a.css`.
2. `</body>` 직전에 스크립트 한 줄. 새 파일 `ui/path-a.js`. 이 파일은 기존 함수가 모두 정의된 뒤에 로드된다.
3. 회원 하단 탭 라벨 한 줄. `render()` 안의 회원 배열 `[['home','홈'],['today','운동시작'],['cal','캘린더조회'],['stat','통계분석'],['me','계정 정보']]`만 바꾼다. 키는 `home` `today` `cal` `stat` `me` 그대로다. 같은 줄의 트레이너 배열 `acal` `day` `quest` `mem` `rec` `cat`은 글자도 바꾸지 않는다.
4. 회원 첫 화면. `tab=S.mode==='admin'?'acal':'home'`에서 회원의 `'home'`만 `'today'`로 바꾼다. 트레이너 `'acal'`은 그대로다.
5. `viewHome()`의 개발자 문장(아바타 폴더 확인 안내) 삭제. 홈의 네 개 큰 버튼은 하단 탭과 같으므로 지운다. 선물함 버튼과 `data-act="gifts"`는 오늘 화면 상단으로 옮긴다. `loadGifts`, `giftsHTML`, `sendGift`는 수정하지 않는다.

`viewToday`, `viewCal`, `viewStat`, `viewMe`, `modePanel`, `fieldBlock`의 계산은 건드리지 않는다. 보이는 위계가 달라야 하면 `ui/path-a.js`에서 기존 함수를 감싼다. 원본 함수는 변수에 보관하고, 같은 이름의 래퍼가 원본 반환값의 숫자와 `data-act`를 유지한 채 껍데기만 바꾼다.

```js
const viewTodayLive = viewToday;
viewToday = function () {
  const html = viewTodayLive();
  // 기존 문자열의 동작 속성(data-act, data-v, id)은 유지하고 껍데기만 바꾼다.
  return html;
};
```

래퍼가 불안하면 그 화면은 라벨만 바꾸고 계산 함수는 중단한다. 동작을 잃는 쪽을 선택하지 않는다.

## 읽기만 하고 수정하지 않는 것

다음 이름과 파일은 존재만 확인하고 본문을 고치지 않는다.

- 저장: `DB.load`, `DB.save`, `persist`, `sv`, `queueSync`, `syncToday`, `syncSoon`, `syFlush`, `syPull`, `syMerge`, `initAuth`, `onSession`, `srvSave`, `srvLoad`
- 상태 키: `localStorage`의 `rpt1`, `rune-theme`. `rpt1`의 최상위는 `user`, `level`, `sessions`, `more`, `curNo`, `drafts`, `profile`, `tiers`, `equip`, `runs`, `adm`, `wm`, `mode`다. `{ version, snapshot }` 모양으로 다시 쓰지 않는다. Path A의 `localRuneRepository.ts`는 같은 키를 다른 모양으로 쓰므로 운영 페이지에 포함하지 않는다.
- 오늘 초안: `S.drafts[날짜].slots[]`의 `id`, `nm`, `sets[]` (`w`, `r`, `t`, `done`, `v`, `lr`, `w2`, `r2`, `car`). 세트 타입 `W` `M` `F`와 옛 값 `N`→`M` 보정은 유지한다.
- 도메인: `EXERCISES`, `BY_ID`, `MODES`, `WM`, `window.RuneTier`, `window.RuneRoutine`, `catRead`, `catWrite`, `tierRows`, `recommend`, `plan`, `fmt`, `esc`
- 서버 테이블과 RPC: `app_state`, `body_measurements`, `exercise_catalog`, `exercise_standards`, `exercise_standards_active`, `member_body`, `profiles`, `push_subscriptions`, `routine_gifts`, `workout_sessions`, `my_record_views`, `trainer_record_feed`. 쿼리 문자열을 바꾸지 않는다.
- 상수: `SB_URL`, `SB_KEY`, `APP_URL`. 값을 프롬프트, 로그, 새 파일, 커밋 메시지로 복사하지 않는다. `redirectTo`는 지금의 `APP_URL`만 쓴다. `code`와 `access_token`을 지우는 `history.replaceState`를 유지한다.
- 파일: `avatar/**`, `sw.js`, `manifest.webmanifest`, 아이콘. 서비스워커 캐시 목록 `SHELL`과 버전 `V`를 이 변경에서 올리지 않는다. 새 `ui/` 파일은 기존 fetch 핸들러가 네트워크에서 받는다.
- 트레이너 화면 함수: `viewAdm`, `viewAdmEdit`, `viewMem`, `viewACal`, `viewDay2`, `viewQuest2`, `viewRec`, `viewCat`.

`ui/path-a.js`는 이 함수들을 호출만 한다. 다시 구현하지 않는다.

## 보안

`design-review/개선-프롬프트.md`의 “하지 말 것”을 그대로 적용한다. 추가로:

- `sb_secret`, `service_role`을 넣지 않는다. 클라이언트 키는 파일에 이미 있는 publishable 키 하나다.
- `innerHTML`에 회원·트레이너 문자열이 들어가면 기존 `esc()`를 탄다.
- `avatarState()`가 지금 보내는 `sex`를 이 패스에서 뺀다. `postMessage`의 두 번째 인자는 `location.origin`만 쓴다. 받는 쪽은 `event.origin === location.origin`이고 `event.source`가 그 iframe인지 확인한다.
- `avatar/avatar.html`이 `sex` 없이 `st`(장비 단계)만으로 그려지는지 확인한다. 성별이 없으면 지금의 기본 체형으로 그리고, 아바타 파일 전체를 다시 쓰지 않는다. 성별이 꼭 있어야 깨지면 아바타 수정은 중단하고 그 사실을 보고한다.
- 근육 뷰어와 아바타에 나이, 키, 체중, 체지방, 부상 메모를 넘기지 않는다.
- 온보딩 나이 8–90, 키 120–230, 체중 25–250, 체지방 3–60(선택)을 넓히지 않는다.
- 의학 효과를 단정하는 문장을 쓰지 않는다.

## 화면

회원 화면만 해당한다. 899px 이하는 지금의 하단 탭, 900px 이상은 사이드 232px다. `#app`의 `max-width: 480px`와 `env(safe-area-inset-*)`는 899px 이하에서 유지한다. 900px 이상에서만 사이드바 때문에 그 너비 제한을 푼다.

탭 문구만 바꾼다. 동작 값은 그대로다.

| 키 | 지금 문구 | 바꿀 문구 |
|---|---|---|
| `today` | 운동시작 | 오늘 |
| `cal` | 캘린더조회 | 달력 |
| `stat` | 통계분석 | 통계 |
| `me` | 계정 정보 | 내 정보 |
| `home` | 홈 | 하단 탭에서는 숨긴다 |

`home` 뷰 함수는 삭제하지 않는다. 선물함·아바타의 구현이 거기 있다. 기본 진입만 오늘이다. 아바타는 `내 정보`에서 `loading="lazy"`로 연다. 첫 화면을 74vh 아바타로 채우지 않는다.

토큰은 새 스타일시트에서만 덮는다. 기존 `--bg` `--pn` `--ln` `--tx` `--mu` `--gd` `--cy` 이름을 지우거나 바꾸지 않는다. 인라인 스타일이 그 이름을 쓴다.

- 배경 `#09090b`, 글자 `#fafafa`, 카드 `#111113`, 보조 글자 `#a1a1aa` 이상, 테두리 `#27272a`, 모서리 12px.
- 라이트는 배경 `#fafafa`, 글자 `#09090b`, 테두리 `#e4e4e7`.
- 글꼴 Pretendard. 본문 14px 이상, 보조 12px 이상. 숫자 입력은 16px 이상. 지금 횟수 입력 19px는 줄이지 않는다.
- 누르는 면은 44px 이상.
- 채운 버튼은 화면마다 하나. 카카오 `#FEE500`은 카카오 버튼만. 금색은 추천 Badge와 티어만.
- 추천 운동 방식은 `modePanel()`의 노란 큰 버튼이 아니라 Badge다. `data-act="wm"`과 `data-v`의 `volume` `strength` `low`는 유지한다. 폭이 좁으면 설명은 선택된 항목 아래에만 둔다.
- “오늘 기록 저장”은 outline이다. `data-act="save"`는 유지한다. 세트 완료가 이미 `persist()`를 타면 저장 버튼을 숨겨도 된다. 저장 실패일 때만 다시 시도를 보인다. 상태 문구는 기존 `syLabel()`이다. 토스트만으로 끝내지 않는다.
- 제목은 “오늘 한 세트가 숙련도가 돼요”. 기존 로그인 안내 문장과 카톡 인앱 안내는 유지한다. “카카오·구글에는 로그인만 맡겨요. 나이, 체중, 부상 기록은 로그인 제공자에게 보내지 않아요.” 한 줄을 더한다.
- 데스크톱 로그인은 왼쪽 설명, 오른쪽 카드. 모바일 로그인 카드는 화면 아래에 붙인다. 로그인 전에 GLB를 받지 않는다.
- 오늘 카드 제목은 “이 종목이 쓰는 근육”. “회전해서 보기”는 다이얼로그를 연다. 주 동작 “이 세트 완료”는 하단 탭 바로 위에 둔다. 본문 아래 여백은 그 높이와 안전 영역만큼 둔다.
- 월드맵 드래그의 `touch-action`은 유지한다. 다이얼로그 드래그가 뒤 페이지를 밀지 않게 한다.
- 달력, 통계, 내 정보는 같은 탭·카드·저장 상태만 맞춘다. 테마 세 칸(`themeSeg`)은 내 정보로 옮긴다. 로그인 화면에는 아이콘 하나만 둔다. 통계의 차트 계산(`radar`, `stTrend`, `viewStat`)은 바꾸지 않는다.

근육 다이얼로그는 `ui/muscle.js`로 추가한다.

- 열릴 때만 같은 출처의 GLB를 받는다. base64로 넣지 않는다. 약 99만 삼각형이므로 실패하면 “모형을 열지 못했어요”와 닫기만 둔다. 포스터와 부위 이름만으로도 성립해야 한다.
- 출처 문장: “BodyParts3D © The Database Center for Life Science, CC BY 4.0. 성인 남성 참고 모형이며 개인 신체나 의학적 소견이 아니에요.”
- 종목과 부위의 대응은 정적 맵이다. 벤치프레스는 가슴. 없는 종목은 모형만 열고 칩은 비운다. 메시 이름이 불확실하면 강조하지 않는다.
- GLB 파일이 저장소에 없으면 이 커밋에 바이너리를 넣지 않는다. 포스터와 이름만 먼저 두고, 모형 파일은 따로 둔다.

## Path A에서 가져오지 않는 것

- React, Vite, Tailwind, shadcn 패키지, `npm run build`를 Pages 배포 조건으로 만들지 않는다. 운영 앱은 빌드 없이 `index.html`을 연다.
- `packages/core`의 `tierCore.ts`로 `window.RuneTier`를 교체하지 않는다. 운영 쪽에는 나이 계수, 풀업, 달리기, 승급 퀘스트, 트레이너 인장이 있다.
- `sampleData.ts`의 회원, 선물, 오늘 운동을 초기 상태로 넣지 않는다. 빈 `rpt1`의 기본값은 지금의 `{user:null, level, sessions:{}, drafts:{}}`다.
- `apps/web`의 `rpt1` version 래퍼, 데모 트레이너 목록, “예시”라는 말을 가져오지 않는다.
- JSX, `lucide-react`를 이 패스에 추가하지 않는다. 아이콘이 필요하면 인라인 SVG다.

## 끝난 기준

- `git diff`에서 `index.html`의 변경은 스타일/스크립트 링크, 탭 라벨, 회원 기본 탭, 홈 문구와 선물함 위치뿐이다. 그 외 동작 변경은 `ui/path-a.css`, `ui/path-a.js`, `ui/muscle.js`에만 있다.
- 트레이너 모드 여섯 탭의 이름과 순서가 같다.
- 기존 `rpt1` JSON을 열었을 때 `sessions`와 `drafts`가 그대로다. 저장 뒤에도 `{version, snapshot}`으로 바뀌지 않는다.
- 카카오·구글 로그인, 세트 저장, 티어, 선물함 수락, 오늘 두 번째 운동(`data-act="newsess"`)이 그대로다.
- 데스크톱 1440과 모바일 390에서 로그인, 오늘, 근육 다이얼로그가 `design-review/proposed/`와 같은 위계다.
- 채운 버튼은 한 화면에 하나다. 카카오 버튼만 노랗다.
- 근육 파일 요청은 다이얼로그를 연 뒤에만 발생한다.
- 뷰어로 나가는 메시지에 성별을 포함한 프로필 필드가 없다.
- `avatar/`, `sw.js`, Supabase 쿼리, 키 상수의 diff가 없다.
